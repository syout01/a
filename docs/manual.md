# 展示会リード フォロー管理ツール 利用マニュアル

対象：展示会後のフォローを回す管理者と、架電・メールを担当するメンバー。
このマニュアルは「操作」と「ランク（セグメント）設計の定義」の両方を扱います。

---

## 1. このツールが解くこと

展示会でバーコードを読んだリストは、そのままでは「誰から、どの順に、何をするか」が決まっていません。
このツールは、その判断を **取り込み時に自動で終わらせ**、担当者は **上から順に電話して結果を記録するだけ** にします。

```
CSV 取り込み → ルールでセグメント判定 → 担当へ配分 → 今日やるリストを上から処理 → 進捗を見る → シートに書き出す
```

展示会後のフォローは鮮度が命です。目安は **翌営業日から 2 週間で全件クローズ** です。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 展示会 | 1 回の出展。CSV はこの単位に取り込む。 |
| リード | 来場者 1 人分の行。会社・氏名・連絡先・ブースメモなど。 |
| セグメント（ランク） | フォローの優先度と「やること」の区分。A：即架電、B：メール後架電、C：ナーチャリング、X：除外、未分類。設定で増減できる。 |
| ルール | 「役職に部長を含む → A」のような判定条件。優先度の小さい順に評価し、最初に一致したものが採用される。 |
| 担当 | そのリードをフォローする人。 |
| ステータス | リードの現在地。未着手 → 架電中 → 通電／資料送付 → アポ獲得／見込みなし。 |
| 次回コール | 再コールする日時。これを入れると、その日まで「今日やるリスト」から消える。 |
| その他の項目 | CSV のうち対応付けしなかった列。判断メモ、ブース名、住所など。フォロー画面の詳細に全部出る。 |

## 3. 役割と 1 日の流れ

### 管理者（展示会の翌営業日）

1. **① 取り込み**：展示会を作成し、CSV をドラッグ＆ドロップ。「判定プレビュー」で件数を確認してから「この内容で取り込む」。
2. **② 振り分けルール**：セグメントの件数比が想定とずれていればルールを直し、「再判定」。
3. **③ 担当割当**：担当者にチェックを入れて「割当を実行」。A ランクが人ごとに均等に配られる。
4. Slack などで「今日やるリストを見て」と周知。

### 担当者（毎日）

1. 右上の「自分」で自分の名前を選ぶ（初回のみ。ブラウザが覚える）。
2. **④ フォロー**を開く。「今日やるリスト」が自分の分だけ、優先度順に並んでいる。
3. 一番上をクリック → 電話 → 結果のステータスを押す → 必要なら次回コールを入れる → メモを 1 行 → 「記録して次へ」。
4. リストが空になったら「期限切れ」に切り替え、再コール漏れがないか確認。

### 管理者（毎日夕方 と 週次）

- **⑤ ダッシュボード**で残件・通電率・アポ数・再コール期限切れを確認。期限切れが増えている担当者には声をかける。
- 週次で **⑥ 書き出し**から Excel またはスプレッドシートに出し、クライアント報告に使う。

## 4. 画面ごとの操作

### ① 取り込み

1. 「展示会を作成」に展示会名・開催日・会場を入れて作成。ヘッダーの展示会セレクタに追加される。
2. CSV をドロップ。文字コード（UTF-8 / Shift_JIS）は自動判別。
3. 「列の対応付け」を確認する。見出しから自動推測されるが、次の 3 つは必ず目で確認する。
   - **氏名**：来場者本人の列になっているか（「担当者の氏名」など自社スタッフの列は自動で除外される）。姓・名が別列なら「姓＋名を結合」。
   - **メール**：見出しが「ログインアカウント」などでも値に @ があれば自動検出される。
   - **既存ランク／担当者名／対応メモ**：チームで既に付けた列があれば対応付ける。既存ランクはルールより優先され、手動固定扱いになる。
4. 「判定プレビュー」を押すと、書き込まずにセグメント別件数・重複数・過去接触数が出る。
5. 「この内容で取り込む」。

重複の判定：同じ展示会内で、メールが同じ、またはメールがなければ「会社名＋氏名」（法人格・空白・全角半角のゆれは吸収）が同じならスキップ。別の展示会に同じ人がいれば取り込んだうえで「過去接触あり」と表示。

### ② 振り分けルール

- ルールは上から（優先度の小さい順）評価され、**最初に一致したセグメント**になる。どれにも当たらなければ「未分類」。
- 条件の演算子：を含む／と一致／で始まる／のいずれかを含む（カンマ区切り）／正規表現／以上・以下（数値）／が空・空でない。
- 「その他の列…」を選ぶと、対応付けしていない CSV 列（例：`あなたの製品導入権限は？`）を条件にできる。
- 「再判定」で今の展示会のリード全件にルールを適用し直す。手動で変えたセグメントは既定で守られる（上書きしたいときはチェックを入れる）。

### ③ 担当割当

- 左の表で「セグメント × 担当」の件数と未割当を確認。
- 右で担当者・対象セグメント・対象（未割当のみ／全件）を選び「割当を実行」。セグメント優先度の高い順に配るので、A も B も人ごとに均等になる。除外セグメントは配られない。
- 下の一覧でチェックを付け、「担当を変更…」「セグメントを変更…」で一括変更。

### ④ フォロー

- 上のフィルタ：今日やるリスト／期限切れ／すべて、担当、セグメント、ステータス、検索。
- 「今日やるリスト」＝自分の担当で、未完了、かつ次回コールが未設定または今日中のもの。
- 右の詳細パネル：電話番号はタップで発信、メールはクリックでメーラーが開く。過去接触があれば前回の状況が黄色で出る。
- ステータスを押し、次回コールを「明日 9時／3日後／1週間後」で入れ、メモを書いて「記録して次へ」。記録すると自動で次のリードが開く。
- セグメントと担当は詳細パネルで個別に変更できる（セグメントの手動変更は固定扱い）。

### ⑤ ダッシュボード

- 上段：総リード数、架電済み、通電率、アポ獲得、アポ率、資料送付、残件、再コール期限切れ。
- セグメント別／担当者別／ステータス分布／日別アクション。「消化率」のバーが伸びない担当者・セグメントがボトルネック。

### ⑥ 書き出し

- Excel：リード一覧・サマリー・セグメント×担当・フォロー履歴の 4 シート。
- CSV：Excel でそのまま開ける UTF-8（BOM 付き）。
- Google スプレッドシート：サーバーにサービスアカウントを設定すると、URL を貼るだけで「リード一覧」「サマリー」「フォロー履歴」タブを作成／上書きする。設定手順は README。

### 設定

- 担当者の追加・停止（停止すると割当候補から外れるが履歴は残る）。
- セグメントの追加・並び順・色・除外フラグ。
- 展示会の名称変更・削除（削除するとリードも消える）。

## 5. ステータスの定義と指標

| ステータス | 意味 | 架電済 | 通電 | 完了 |
| --- | --- | :-: | :-: | :-: |
| 未着手 | まだ一度も接触していない | | | |
| 架電中（不在・再コール） | かけたが本人と話せていない。次回コール必須 | ○ | | |
| 通電（継続フォロー） | 本人と話せた。アポには至らず継続 | ○ | ○ | |
| 資料送付 | 資料を送った。送付後の再コール日を入れる | ○ | ○ | |
| アポ獲得 | 商談日時が確定 | ○ | ○ | ○ |
| 見込みなし | 本人と話し、当面ニーズなし | ○ | ○ | ○ |
| 対象外 | 同業・学生・連絡先不備などフォローしない | | | ○ |

- 通電率 ＝ 通電 ÷ 架電済（目安：展示会リードは 40〜60%）
- アポ率 ＝ アポ獲得 ÷ 通電（目安：A ランクで 20〜30%、全体で 10〜15%）
- 「見込みなし」は本人と話したうえで判断したものだけ。話せていないのに見込みなしにすると通電率が狂う。

## 6. ランク（セグメント）設計ガイド

### 6.1 ランクが曖昧になる典型パターン

| 症状 | 起きること |
| --- | --- |
| 「A＝良さそう」と感覚で付けている | 人によって A の基準が違い、架電順が信用されなくなる |
| 役職の高さと興味の強さを 1 つの記号に混ぜている | 「興味は薄いが社長」と「担当者だが見積もり希望」が同じ B になり、優先順位が逆転する |
| ランクの「出口」が決まっていない | A と B で結局やることが同じになり、ランクを付ける意味がなくなる |
| 商材が違うのに全社共通のランクを使い回す | 研修商材では良い先（従業員 300 名）が、SaaS では対象外、のような食い違いが埋もれる |
| 判断の根拠が残っていない | 後から「なぜ B だったか」が分からず、見直しができない |

### 6.2 設計の型：2 軸 × 出口

ランクは **「誰が」×「どれくらい今欲しいか」** の 2 軸で決め、**ランクごとに次のアクションと期限を必ず 1 つ** 決めます。

**軸 1：決裁関与度**

| 段階 | 定義 | 判定に使う情報 |
| --- | --- | --- |
| 高 | 決裁者、または導入権限がある | 役職（代表・役員・本部長・部長）、アンケート「導入権限がある」 |
| 中 | 決裁には関与するが最終決定者ではない | 課長・マネージャー・主任、「導入に関与している」 |
| 低 | 権限も関与もない | 一般・担当、「導入権限がない」、学生 |

**軸 2：温度（ニーズとタイミング）**

| 段階 | 定義 | 判定に使う情報 |
| --- | --- | --- |
| 高 | 具体的に検討している。課題・時期・予算のいずれかを口にした | ブースメモに「検討」「見積」「導入」「来期」「相談」「課題」 |
| 中 | 興味はあるが具体化していない。資料や事例を求めた | 「興味」「資料」「事例」「また連絡」 |
| 低 | 情報収集・立ち寄り・ノベルティ目的 | 「情報収集」「とりあえず」、メモなし |

**マトリクス（既定）**

| | 温度 高 | 温度 中 | 温度 低 |
| --- | :-: | :-: | :-: |
| 決裁関与 高 | **S**（または A） | **A** | **B** |
| 決裁関与 中 | **A** | **B** | **C** |
| 決裁関与 低 | **B** | **C** | **C** |

同業・競合・学生・個人・連絡先不備は、この表に入る前に **X（対象外）** に落とします。

### 6.3 ランク定義テンプレート

各ランクは、この 5 項目が埋まって初めて「定義された」と言えます。空欄があるうちは曖昧です。

| ランク | 定義（条件） | 次のアクション | 期限 | 誰が |
| --- | --- | --- | --- | --- |
| S | 決裁関与 高 × 温度 高 | 担当が電話。出なければ責任者から携帯へ | **当日中** | 責任者 |
| A | 決裁関与 高 × 温度 中、または 中 × 高 | お礼メール → 翌日電話。アポ打診まで一気に | 翌営業日〜3 営業日 | 担当 |
| B | 高 × 低、中 × 中、低 × 高 | お礼メール（事例つき）→ 3 日後に電話 | 1 週間以内に初回接触 | 担当 |
| C | 中 × 低、低 × 中、低 × 低 | メルマガ・セミナー案内に登録。電話は余力があれば | 2 週間以内にメール 1 通 | 管理者が一括 |
| X | 同業・競合・学生・個人・連絡先不備 | しない | ― | ― |

**S を作るべきか**：S は「当日中」「責任者が出る」のように **運用が A と本当に変わるとき** だけ作ります。運用が同じなら A に含めた方がブレません。

**F と X の違い**：X は「そもそも対象外」、F は「一度フォローして見込みなしと判断した」です。F を使う場合はステータス「見込みなし」と役割が重なるので、どちらか一方に寄せてください。ツールではステータス側に寄せるのを推奨します。

### 6.4 企業（商材）ごとの調整方法

軸の定義は共通のまま、**「商材に合う会社か」を X／C の条件として追加**します。ランク体系を企業ごとに作り直さない方が、担当者が複数案件を掛け持ちしても迷いません。

| 商材タイプ | 適合の軸 | ルール例 |
| --- | --- | --- |
| 研修・人材系 | 従業員数 | 従業員 50 名未満 → C、教育・官公庁 → X |
| 業務 SaaS | 業種・部署 | 対象業種以外 → C、情シス以外の部署でも決裁者なら A のまま |
| 代行・アウトソース | 部署・課題 | 営業部門で「人手不足」「リソース」 → 温度 +1 段階 |
| 高単価・BtoB 設備 | 会社規模・上場区分 | 売上 10 億未満 → C、上場 or 100 億以上 → 決裁関与 +1 段階 |

「+1 段階」は、ルールを 1 本追加してそのセグメントを直接指定することで表現します。

### 6.5 ツールへの落とし込み

ルールの優先度番号は次の帯で付けると読みやすく、後から差し込めます。

| 優先度 | 用途 |
| --- | --- |
| 1〜19 | 除外（X）。同業・競合・学生・個人アドレス・連絡先不備 |
| 20〜29 | S／A。導入権限あり、経営・部長クラス、温度 高のメモ |
| 30〜39 | B。課長・主任クラス、導入に関与、温度 中のメモ |
| 40〜49 | 商材適合の補正（規模・業種で C に落とす など） |
| 90〜 | C。残り全部（会社名が空でない） |

判定に使う情報の優先順位は **①ブースメモ（温度） → ②導入権限アンケート → ③役職レベルアンケート → ④役職テキスト → ⑤会社規模・業種**。上にあるほど「その人の今」を表しているためです。

既にチームでランクを付けた CSV は、「既存ランク → セグメント」に対応付ければそのまま採用されます（手動固定扱い）。ランクの値（S/A/B/C/F）に対応するセグメントを設定で用意しておくと、取り込み時に全件そのまま入ります。

### 6.6 判断メモの書き方

セグメントを手動で変えるとき、ブースメモ欄または対応メモに **根拠を 1 行** 残します。形は「事実 → 判断」。

- 良い例：「規模不明・管理職から 10 名以上と推定 → B」
- 良い例：「役職未記入・役職レベル『一般・その他』で判定 → C」
- 悪い例：「良さそう」「微妙」

この 1 行があると、6.7 の見直しで「どの根拠が外れやすいか」が分かります。

### 6.7 キャリブレーション（定義を育てる手順）

1. **取り込み直後**：「未分類」を全件と、A から 20 件をサンプルで目視。未分類が 10% を超えるならルールの網が粗い。A に「情報収集のみ」が混じるなら温度条件を締める。
2. **1 週間後**：ダッシュボードのセグメント別で、A の「通電後に見込みなし」比率を見る。30% を超えるなら A の条件が緩い。B からアポが出ているなら、その共通点を A の条件に昇格させる。
3. **2 週間後（クローズ時）**：ランク別アポ率を記録。次の展示会のルールの初期値にする。
4. 変更はルールを直して「再判定」。手動で固定した分は守られるので、判断メモがある行は上書きされない。

### 6.8 定義シート（記入用）

展示会ごと、または商材ごとに 1 枚。埋めてから取り込みを始めます。

```
展示会名：                 商材：                 記入者：            日付：
[軸 1 決裁関与] 高＝                中＝                低＝
[軸 2 温度]     高＝                中＝                低＝
[商材適合]      X にする条件＝                     C に落とす条件＝
[ランク別の出口]
  S：アクション＝           期限＝        誰が＝
  A：アクション＝           期限＝        誰が＝
  B：アクション＝           期限＝        誰が＝
  C：アクション＝           期限＝        誰が＝
[見直し予定日] 1 週間後＝          クローズ＝
```

## 7. よくある質問

**Q. 取り込んだら未分類だらけになった**
A. 役職が空、またはメモが無い CSV です。②で「その他の列…」からアンケート列（役職レベル・導入権限）を条件に使うか、会社規模・業種でルールを足してください。

**Q. 同じ人が 2 回スキャンされている**
A. 同じ展示会内ならメールで自動的に 1 件にまとまります。メールが無いリストは会社名＋氏名で判定します。

**Q. 電話番号の先頭の 0 が消えている**
A. Excel の仕様です。取り込み時に 9〜10 桁で 0 始まりでない番号には自動で 0 を補います。

**Q. 担当者を辞めた人はどうする**
A. 設定で「停止」にすると割当候補から外れます。残っていたリードは③で未割当フィルタから他の人に配り直します。

**Q. クライアントに進捗を見せたい**
A. 現状は ⑥ 書き出しの Excel／スプレッドシートを共有してください。閲覧専用ログインは Web 化の計画（docs/webapp-plan.md）に含めています。

**Q. データはどこにある**
A. サーバーの `data/app.db` 1 ファイルです。バックアップはこのファイルをコピーするだけです。
