# クラウドに載せる手順（Render 編）

「自分の PC で `npm start` する」状態から、「URL を開いてログインすれば全員が使える」状態にする手順です。
プログラミングの知識は不要で、ブラウザ操作と GitHub の権限があれば進められます。所要 30 分程度。

## 全体像

```
GitHub のリポジトリ ──(自動ビルド)──▶ Render の Web サービス ──▶ https://xxxx.onrender.com
                                            └─ 永続ディスク /data（SQLite と日次バックアップ）
```

- リポジトリに入っている `Dockerfile` と `render.yaml` を Render が読み、サーバーを組み立てます。
- データはディスクに 1 ファイル（`/data/app.db`）で保存され、毎日自動でバックアップが 14 世代残ります。
- HTTPS 証明書は Render が自動で発行・更新します。

## 費用の目安

| 項目 | 月額 |
| --- | --- |
| Web サービス Starter（永続ディスクを使うために必要） | 約 7 USD |
| 永続ディスク 1 GB | 約 0.25 USD |
| 独自ドメイン（任意。お名前.com 等） | 年 1,000〜3,000 円 |

無料プランはディスクが使えず、放置するとサーバーが眠ってデータも消えるので使いません。

## 手順

### 1. Render アカウントを作る
1. https://render.com を開き、「Get Started」→ **GitHub でサインアップ**。
2. GitHub の認可画面で、このリポジトリ（`syout01/a`）へのアクセスを許可します。

### 2. Blueprint からサービスを作る
1. Render のダッシュボード右上「New +」→ **Blueprint**。
2. リポジトリ一覧から `syout01/a` を選び、ブランチに `claude/exhibition-barcode-list-management-ztnc07`（main に取り込んだ後は `main`）を指定。
3. `render.yaml` の内容が読み込まれ、サービス名 `expo-lead-followup`、Starter プラン、ディスク 1 GB が表示されます。
4. 環境変数 `APP_URL` の入力を求められたら、いったん空のまま進めて構いません（後で設定）。
5. 「Apply」。5 分ほどでビルドが終わり、`https://expo-lead-followup-xxxx.onrender.com` のような URL が発行されます。

### 3. 最初の管理者を作る
1. 発行された URL をブラウザで開きます。管理者がまだいないので「最初の管理者を作成」画面が出ます。
2. 名前・メールアドレス・パスワード（10 文字以上、英字と数字を含む）を入れて作成。これがあなたのログイン ID です。
3. **この画面は最初の 1 回しか出ません**。以降は必ずログイン画面になります。

### 4. APP_URL を設定する（招待リンクの宛先）
1. Render のサービス画面 → 「Environment」 → `APP_URL` に発行された URL（`https://expo-lead-followup-xxxx.onrender.com`）を入れて保存。
2. 自動で再デプロイされます（1〜2 分）。

### 5. メンバーを招待する
1. ツールにログインし、「設定」→「メンバー」で名前・メールアドレス・権限を入れて追加。
2. 行の「招待リンク」を押すとリンクが表示されます。「コピー」して、本人に Slack や社内チャットで渡してください（リンクは 7 日間有効、1 回限り）。
3. 本人がリンクを開き、名前とパスワードを設定するとログインできます。
4. パスワードを忘れた人には、同じ行の「再設定リンク」を発行して渡します（24 時間有効）。

メールアドレスを入れずに追加したメンバーは「担当者としてだけ」存在し、割当先には選べますがログインはしません（電話だけ担当する人など）。

### 6. 独自ドメインを付ける（任意）
1. Render のサービス画面 → 「Settings」 → 「Custom Domains」 → 例 `leads.example.co.jp` を追加。
2. 表示される CNAME をドメイン管理画面（お名前.com など）に登録。
3. 反映後、`APP_URL` を独自ドメインの URL に変えて保存。

### 7. バックアップを手元にも置く
- 「設定」→「バックアップ」→「今すぐバックアップをダウンロード」で、その時点の DB ファイルが落ちます。月 1 回、社内の共有ドライブに保存してください。
- サーバー側にも毎日自動で 14 世代残ります（`/data/backups`）。

## 更新の流れ

ツールを直したら、GitHub のそのブランチに push するだけで Render が自動で再ビルド・再起動します。データはディスクに残るので消えません。

## トラブル時

| 症状 | 見る場所・対処 |
| --- | --- |
| URL を開くとエラー | Render の「Logs」タブ。ビルド失敗なら赤字の行を送ってください |
| 招待リンクの先頭が `http://localhost` になっている | `APP_URL` が未設定。手順 4 を実施 |
| ログインできない（管理者が自分だけ） | Render の「Shell」タブで `node -e` を使い再設定できます。連絡ください |
| 動作が遅い | Starter は 0.5 CPU / 512 MB。数万件規模までは十分。超えるならプランを上げる |

## Render 以外を使う場合

`Dockerfile` は汎用なので、Fly.io、さくらの VPS、AWS Lightsail などでも同じイメージで動きます。必要なのは「永続ディスクを `/data` にマウントする」「`APP_URL` を設定する」「HTTPS で公開する」の 3 点です。
